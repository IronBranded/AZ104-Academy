# Lab 04-03 - Name Resolution and Load Balancing

**Objective:** Configure name resolution and load balancing
**Estimated cost:** Medium - two small B-series Linux VMs **without** public IPs, and a Standard public load
balancer with a Standard public IP, for about an hour. Plus a public DNS zone and a private DNS zone, billed per
zone and per query. Delete everything the same day.
**Licensing required:** None beyond an Azure subscription.

> Complete **04-01** and **04-02** first. No Bastion is needed: you run commands on the VMs with
> `az vm run-command invoke`, through the VM agent, so no inbound port is opened for management.
>
> New virtual networks have **private subnets** (04-01), so the VMs can't download packages. The lab serves web
> pages with Python, which is already on Ubuntu.

Portal steps were checked against Microsoft Learn on 2026-10-01.

## Why this matters

Users and services find applications by name, and one server is a single point of failure. An administrator hosts DNS names and spreads traffic across several backends, keeping it away from any backend that stops responding.

## The desired state

When you finish, these will be true. Each one is checked in **Validation** below.

- A **private DNS zone** where VMs register their own names.
- Two VMs behind a **Standard public load balancer** with a health probe and a rule.
- A **public DNS zone** with an **alias** record at the apex pointing at the load balancer's public IP.
- A broken probe and a broken backend, each found and fixed.

## Part 1 - A private DNS zone with auto-registration

Create the zone and the registration link **before** the VMs, so they're registered as they're created:

```powershell
az network private-dns zone create --resource-group $Rg --name az104lab.internal
az network private-dns link vnet create --resource-group $Rg --zone-name az104lab.internal `
  --name link-0403 --virtual-network vnet-az104-0403 --registration-enabled true

foreach ($v in 'vm-a','vm-b') {
  az vm create --resource-group $Rg --name $v --image Ubuntu2204 --size $Size `
    --vnet-name vnet-az104-0403 --subnet web --public-ip-address '""' --nsg '""' `
    --admin-username azureuser --generate-ssh-keys --tags az104-module=$LabId
}

az network private-dns record-set a list --resource-group $Rg --zone-name az104lab.internal `
  --query "[].{name:name, ip:aRecords[0].ipv4Address}" -o table
```

Both VMs appear as **A records** you never created. Resolve one from the other, without Bastion:

```powershell
az vm run-command invoke --resource-group $Rg --name vm-a --command-id RunShellScript `
  --scripts "getent hosts vm-b.az104lab.internal" --query "value[0].message" -o tsv
```

## Part 2 - A web page on each VM

Each VM serves a page naming itself, on port 80, through a transient systemd unit that keeps running after the
command returns:

```powershell
foreach ($v in 'vm-a','vm-b') {
  az vm run-command invoke --resource-group $Rg --name $v --command-id RunShellScript --scripts `
    "mkdir -p /var/www/lab && hostname > /var/www/lab/index.html && systemd-run --unit=lab-web /usr/bin/python3 -m http.server 80 --directory /var/www/lab" `
    --query "value[0].message" -o tsv
}
```

## Part 3 - A Standard public load balancer

```powershell
az network public-ip create --resource-group $Rg --name pip-lb-0403 --sku Standard --allocation-method Static
az network lb create --resource-group $Rg --name lb-0403 --sku Standard --public-ip-address pip-lb-0403 `
  --frontend-ip-name fe-web --backend-pool-name be-web
az network lb probe create --resource-group $Rg --lb-name lb-0403 --name probe-http --protocol Http --port 80 --path /
az network lb rule create --resource-group $Rg --lb-name lb-0403 --name rule-http --protocol Tcp `
  --frontend-port 80 --backend-port 80 --frontend-ip-name fe-web --backend-pool-name be-web --probe-name probe-http

foreach ($v in 'vm-a','vm-b') {
  $nic = (az vm show -g $Rg -n $v --query "networkProfile.networkInterfaces[0].id" -o tsv).Split('/')[-1]
  az network nic ip-config address-pool add --resource-group $Rg --nic-name $nic --ip-config-name ipconfig1 `
    --lb-name lb-0403 --address-pool be-web
}

$lbIp = az network public-ip show -g $Rg -n pip-lb-0403 --query ipAddress -o tsv
1..6 | ForEach-Object { try { (Invoke-WebRequest "http://$lbIp" -UseBasicParsing -TimeoutSec 5).Content.Trim() } catch { 'timeout' } }
```

**Timeouts.** The probes may already be healthy (open **Health probes** or **Insights**), yet clients can't get
in: a **Standard** load balancer is **secure by default**. Allow the client traffic with an NSG on the subnet:

```powershell
az network nsg create --resource-group $Rg --name nsg-web-0403
az network nsg rule create --resource-group $Rg --nsg-name nsg-web-0403 --name allow-http --priority 100 `
  --direction Inbound --access Allow --protocol Tcp --source-address-prefixes Internet --destination-port-ranges 80
az network vnet subnet update --resource-group $Rg --vnet-name vnet-az104-0403 --name web --network-security-group nsg-web-0403

1..6 | ForEach-Object { try { (Invoke-WebRequest "http://$lbIp" -UseBasicParsing -TimeoutSec 5).Content.Trim() } catch { 'timeout' } }
```

Now the answers name **vm-a** and **vm-b**. Each request is a new flow with a new source port, so the 5-tuple hash
spreads them.

## Part 4 - A public DNS zone with an alias at the apex

```powershell
$Zone = "az104lab$n.com"       # not a real delegated domain: you query Azure's name servers directly
az network dns zone create --resource-group $Rg --name $Zone
$ns = az network dns zone show -g $Rg -n $Zone --query "nameServers[0]" -o tsv

$pipId = az network public-ip show -g $Rg -n pip-lb-0403 --query id -o tsv
az network dns record-set a create --resource-group $Rg --zone-name $Zone --name "@" --target-resource $pipId
az network dns record-set cname set-record --resource-group $Rg --zone-name $Zone --record-set-name www --cname $Zone

Resolve-DnsName -Name $Zone -Server $ns -Type A           # the load balancer's IP, from an alias record
Resolve-DnsName -Name "www.$Zone" -Server $ns             # CNAME to the apex, then the alias
```

Try making a CNAME at the apex instead. The service refuses it:

```powershell
az network dns record-set cname set-record --resource-group $Rg --zone-name $Zone --record-set-name "@" --cname www.example.com
```

In the portal, open the zone and its **NS** record: these are the four name servers you would give your registrar
to delegate a real domain.

## Part 5 - Break it, then troubleshoot it

**A probe blocked by an NSG.** Deny the probe source above the default allow:

```powershell
az network nsg rule create --resource-group $Rg --nsg-name nsg-web-0403 --name deny-probe --priority 110 `
  --direction Inbound --access Deny --protocol Tcp --source-address-prefixes AzureLoadBalancer --destination-port-ranges 80
```

Within a probe interval or two, **Insights** and the **Health Probe Status** metric show both backends **down**, and
requests to `$lbIp` fail, although both VMs and their web servers are fine. Find the cause the way you would in
production:

```powershell
$nicA = (az vm show -g $Rg -n vm-a --query "networkProfile.networkInterfaces[0].id" -o tsv).Split('/')[-1]
az network nic list-effective-nsg --resource-group $Rg --name $nicA `
  --query "value[].effectiveSecurityRules[?contains(name,'deny-probe')].{name:name, priority:priority, access:access}" -o json
az network nsg rule delete --resource-group $Rg --nsg-name nsg-web-0403 --name deny-probe
```

**A backend that stops listening.** Stop the web server on vm-b only:

```powershell
az vm run-command invoke -g $Rg -n vm-b --command-id RunShellScript --scripts "systemctl stop lab-web" --query "value[0].message" -o tsv
1..6 | ForEach-Object { try { (Invoke-WebRequest "http://$lbIp" -UseBasicParsing -TimeoutSec 5).Content.Trim() } catch { 'timeout' } }
```

After the probe marks vm-b down, every answer is **vm-a**: no new flows go to a failing backend. In **Insights**, compare
**Data Path Availability** (still up: a healthy backend remains) with **Health Probe Status** (half the pool down).

**Walkthrough: internal load balancer.** An internal load balancer is the same build with a **private** frontend IP from a
subnet. Its backends can't call its own frontend.

## What just happened?

DNS and load balancing worked together. The private zone resolved names only for linked networks, and auto-registration created the VM records for you. The load balancer worked at Layer 4: a health probe decided which backends received **new** flows, and a Standard load balancer stayed closed until an NSG allowed the client traffic. The alias record pointed at the public IP resource rather than at an address, so it follows the IP if it changes.
