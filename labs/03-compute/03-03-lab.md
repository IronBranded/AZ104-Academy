# Lab 03-03 - Containers

**Objective:** Provision and manage containers in the Azure portal
**Estimated cost:** Low - a Basic container registry (billed per day), two small container groups that run
for minutes (billed per second), and a container app that scales to zero. The Container Apps environment
creates a Log Analytics workspace, which bills for the small amount it ingests. Delete everything the
same day.
**Licensing required:** None beyond an Azure subscription.

> Complete **01-02** first: this lab assigns the AcrPull role. **Delete the container groups as soon as
> Part 3 is done**; they bill for every second they run.

Portal steps were checked against Microsoft Learn on 2026-09-30.

## Why this matters

Teams package applications as container images. An administrator needs a private place to store those images, a way to run them without managing servers, and control over how they're sized and scaled.

## The desired state

When you finish, these will be true. Each one is checked in **Validation** below.

- A private **Azure Container Registry** with an imported image and the **admin user disabled**.
- A **managed identity** with **AcrPull**, used to pull the image.
- **Container Instances** runs: a long-running service and a one-off task, both then deleted.
- A **Container App** with ingress, scale-to-zero and **revisions** with traffic splitting.

## Prerequisites

- **Owner** on the lab subscription, or Contributor plus User Access Administrator. You assign AcrPull
  to identities.
- The Azure CLI with the Container Apps extension:

```powershell
az extension add --name containerapp --upgrade
az provider register --namespace Microsoft.App
az provider register --namespace Microsoft.OperationalInsights
az provider register --namespace Microsoft.ContainerInstance

$LabId = '03-03'
$Rg    = "rg-az104-lab-$LabId"
$Loc   = '<region>'
$n     = Get-Random -Maximum 99999
$Acr   = "az104lab0303$n"            # 5-50 alphanumeric, globally unique
az group create --name $Rg --location $Loc --tags az104-module=$LabId
```

## Part 1 - A registry, and an image imported without Docker

```powershell
az acr create --resource-group $Rg --name $Acr --sku Basic --tags az104-module=$LabId
az acr show --name $Acr --query "{loginServer:loginServer, sku:sku.name, adminUser:adminUserEnabled}" -o table

az acr import --name $Acr --source mcr.microsoft.com/azuredocs/aci-helloworld:latest --image hello:v1
az acr repository show-tags --name $Acr --repository hello -o table
```

The admin user is **disabled**. Leave it that way: this lab pulls with managed identities.

In the portal, open the registry > **Replications**. Geo-replication needs **Premium**; the page offers an
upgrade. Don't take it.

## Part 2 - An identity that can pull

Container Instances can pull from ACR only with a **user-assigned** managed identity, so create one and
give it **AcrPull** on the registry:

```powershell
$uamiId  = az identity create --resource-group $Rg --name id-az104-0303 --query id -o tsv
$uamiPid = az identity show   --ids $uamiId --query principalId -o tsv
$acrId   = az acr show --name $Acr --query id -o tsv

az role assignment create --assignee-object-id $uamiPid --assignee-principal-type ServicePrincipal `
  --role AcrPull --scope $acrId
```

Role assignments can take a few minutes to take effect (01-02). If Part 3 fails with an authorization
error, wait and retry.

## Part 3 - Container Instances: a service, a size you can't change, and a task

**A service container group**, pulling the private image:

```powershell
$label = "az104-0303-$n"
az container create --resource-group $Rg --name aci-hello `
  --image "$Acr.azurecr.io/hello:v1" --os-type Linux --cpu 1 --memory 1.5 `
  --ports 80 --dns-name-label $label --restart-policy Always `
  --assign-identity $uamiId --acr-identity $uamiId

az container show --resource-group $Rg --name aci-hello --query "{fqdn:ipAddress.fqdn, state:instanceView.state}" -o table
```

Open the FQDN in a browser. Then:

```powershell
az container logs --resource-group $Rg --name aci-hello

# Try to give it more CPU by redeploying with the same name. This is refused:
# CPU, memory, restart policy, OS type and zone require delete and re-create.
az container create --resource-group $Rg --name aci-hello `
  --image "$Acr.azurecr.io/hello:v1" --os-type Linux --cpu 2 --memory 1.5 `
  --ports 80 --dns-name-label $label --restart-policy Always `
  --assign-identity $uamiId --acr-identity $uamiId

# Keep its definition as YAML: the starting point for a re-create
az container export --resource-group $Rg --name aci-hello --file aci-hello.yaml
```

**A task container group** that runs once and stops:

```powershell
az container create --resource-group $Rg --name aci-task `
  --image "$Acr.azurecr.io/hello:v1" --os-type Linux --cpu 1 --memory 1 `
  --command-line "echo task-complete" --restart-policy Never `
  --assign-identity $uamiId --acr-identity $uamiId

az container show --resource-group $Rg --name aci-task --query instanceView.state -o tsv   # Succeeded
az container logs --resource-group $Rg --name aci-task                                     # task-complete
```

Now **delete both groups**. They bill per second while they run.

```powershell
az container delete --resource-group $Rg --name aci-hello --yes
az container delete --resource-group $Rg --name aci-task  --yes
```

## Part 4 - Container Apps: ingress, scale to zero, a private image

```powershell
az containerapp env create --name cae-az104-0303 --resource-group $Rg --location $Loc

az containerapp create --name ca-az104-0303 --resource-group $Rg --environment cae-az104-0303 `
  --image mcr.microsoft.com/k8se/quickstart:latest --ingress external --target-port 80 `
  --min-replicas 0 --max-replicas 3 `
  --scale-rule-name http --scale-rule-type http --scale-rule-http-concurrency 10

$fqdn = az containerapp show --name ca-az104-0303 --resource-group $Rg --query properties.configuration.ingress.fqdn -o tsv
Invoke-WebRequest "https://$fqdn" -UseBasicParsing | Select-Object StatusCode
az containerapp replica list --name ca-az104-0303 --resource-group $Rg -o table     # one or more replicas
```

Leave it alone for a while, with no requests, and list the replicas again. They go to **zero**, and
nothing bills for usage while they're there. The next request starts a replica.

Now switch to the **private** image, pulled with the app's **system-assigned** identity:

```powershell
az containerapp registry set --name ca-az104-0303 --resource-group $Rg --identity system --server "$Acr.azurecr.io"
az containerapp update --name ca-az104-0303 --resource-group $Rg --image "$Acr.azurecr.io/hello:v1"
```

In the portal, open the app > **Identity** > **System assigned** > **Azure role assignments**, and check that
**AcrPull** is there. If the pull failed because it wasn't, assign it yourself:

```powershell
$appPid = az containerapp show --name ca-az104-0303 --resource-group $Rg --query identity.principalId -o tsv
az role assignment create --assignee-object-id $appPid --assignee-principal-type ServicePrincipal --role AcrPull --scope $acrId
```

## Part 5 - Revisions and traffic splitting

```powershell
az containerapp revision set-mode --name ca-az104-0303 --resource-group $Rg --mode multiple

# A second revision: same image, a changed environment variable, a readable suffix
az containerapp update --name ca-az104-0303 --resource-group $Rg --revision-suffix v2 --set-env-vars RELEASE=v2

az containerapp revision list --name ca-az104-0303 --resource-group $Rg `
  --query "[].{name:name, active:properties.active, traffic:properties.trafficWeight}" -o table
```

Split traffic 80/20 between the previous revision and `ca-az104-0303--v2`, using the names from the list:

```powershell
az containerapp ingress traffic set --name ca-az104-0303 --resource-group $Rg `
  --revision-weight "<previous-revision-name>=80" "ca-az104-0303--v2=20"
```

In the portal, **Revisions and replicas** shows both revisions active, with the weights you set. The weights
must add up to 100.

```powershell

az container list --resource-group $Rg -o table                                       # nothing: both deleted
az containerapp show --name ca-az104-0303 --resource-group $Rg `
  --query "{mode:properties.configuration.activeRevisionsMode, min:properties.template.scale.minReplicas, max:properties.template.scale.maxReplicas}" -o table
```

## What just happened?

The registry stored the image; the compute services only **pulled** it, using an identity with a role on the registry rather than a shared password. Container Instances ran exactly the size you asked for and didn't scale by rules. Container Apps scaled replicas by rule, down to zero, and kept old revisions so traffic could be split between versions.

## Teardown

### 1. Resources

```powershell
az group delete --name $Rg --yes
Remove-Item ./aci-hello.yaml -ErrorAction SilentlyContinue
```

This removes the registry and its image, the identity, the environment, the app, and the Log Analytics
workspace the environment created.

### 2. Subscription scope

The AcrPull role assignments were scoped to the registry. Check that none are left as orphans; list
without `-Scope` so every scope is included:

```powershell
Get-AzRoleAssignment | Where-Object { -not $_.DisplayName } | Select-Object RoleDefinitionName, Scope
```

### 3. Directory scope

None. Managed identities are deleted with their resources.

### 4. Soft-deleted remains

The Log Analytics workspace created by the environment can remain **soft-deleted for up to 14 days**
(00-02). Re-creating a workspace with the same name in that window recovers it rather than creating a new
one.

### 5. Access

Remove any role you added to your working account only for this lab.

### 6. Verify

```powershell
az group exists --name $Rg                                       # false
az acr list --query "[?contains(name,'az104lab0303')].name" -o tsv    # nothing
```

Tick these once the commands above return what's expected. The lab counts as **practised** only when the validation and teardown checklists are both complete.

- [ ] `az group exists` for the lab resource group returns **false**.
- [ ] No registry named `*az104lab0303*` remains.
